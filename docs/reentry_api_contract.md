# RE-ENTRY unified snapshot contract

RE-ENTRY has one operational decision source: `REENTRY_UNIFIED_v1`.

The dashboard must never recompute strategy logic and must never substitute a legacy completed-close, analog, sector/factor, or separate intraday decision when the unified snapshot is missing or degraded.

## Canonical snapshot

Primary research-branch artifact:

`data/reentry/exhaustion_intraday_current.json`

The frontend reads this object through `web/lib/unifiedReentry.ts`.

Required decision fields:

- `unified_engine.engine_version`
- `unified_engine.decision` in `WAIT | WATCH | GO_EARLY`
- `unified_engine.state`
- `unified_engine.oversold_gate`
- `unified_engine.fast_family_count`
- `unified_engine.context_support_count`
- `unified_engine.context_support`
- `unified_engine.market_phase`
- `unified_engine.timestamp_et`
- `unified_engine.market_date`

Required fast-family fields:

- `families.fast_breadth_turn`
- `families.momentum_turn`
- `families.net_volume_turn`
- `families.down_up_ratio_relief`

Required context families:

- `MMFD_IMPROVING`
- `NASI_TURNING_UP`
- `VVIX_EASING`
- `SKEW_NARROWING`

## Market phase

The same engine runs throughout the session.

- `LIVE_PROVISIONAL` during the regular session
- `CLOSE_SETTLING` immediately after 16:00 ET
- `MARKET_CLOSED_FINAL` after the close-settling buffer

There is no separate intraday strategy and no separate completed-close strategy.

## Data quality

The finalized snapshot contains `data_quality.status`:

- `OK`
- `PARTIAL`
- `DEGRADED`

If status is `DEGRADED`, the UI must display `DATA DEGRADED` and must not present the underlying decision as actionable. The underlying calculation remains in the object for auditability.

Display-only SPY, QQQ, and VIX market-price context is explicitly marked `decision_input: false`.

## Provenance

The finalized object includes a `sources` section covering fast breadth, NASI+, MMFD, VVIX, and SKEW. Where a source timestamp is unavailable, the UI must say so rather than inventing freshness.

## Prospective validation

`data/reentry/unified_engine_history.csv` and the immutable prospective snapshot ledger are the point-in-time evidence base for the current engine.

Old historical evidence generated by retired strategies must not be relabeled as `REENTRY_UNIFIED_v1` validation.

Shadow persistence variants and CPCE research have `engine_impact: NONE` and cannot change the operational decision.

## Frontend failure behavior

If the canonical unified snapshot cannot be loaded, the page must display `RE-ENTRY unavailable` and explicitly state that no legacy decision is substituted.

## Freeze rule

During the Vercel freeze, all changes remain on `intraday-signal-research`. GitHub Actions regression tests and a local Next.js production build are the required QA path. No Vercel preview or production deployment is permitted until the freeze is explicitly lifted.
